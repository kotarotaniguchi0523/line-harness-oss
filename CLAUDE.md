# LINE Harness OSS

## Project Overview

LINE Official Account CRM/marketing automation platform. Open-source alternative to L-Message and U-tou.
Manages friends, tag-based segmentation, step scenarios, broadcasts, automations, chat, scoring, reminders, conversions, and affiliates.

## Architecture

- **Monorepo**: pnpm workspaces + Turborepo
- **Frontend**: TanStack Start (TanStack Router, file-based routes, deployed to CF Pages)
- **Backend**: Cloudflare Workers + Hono v4
- **RPC**: Cap'n Web (capnweb) for object-capability RPC, promise pipelining, HTTP batch
- **Database**: Cloudflare D1 (SQLite) via Drizzle ORM
- **Validation**: Zod schemas in packages/contracts (single source of truth)
- **State**: TanStack Query (server state) + TanStack Store (client state)
- **Forms**: TanStack Form + Zod
- **CSS**: Panda CSS (type-safe design tokens, `strictTokens: true`)
- **Secrets**: Doppler (all environments)
- **Env**: t3-env (type-safe environment variables)
- **LINE API**: Direct fetch + Zod schemas in packages/line-api (NO @line-official-account SDK)
- **Build**: Turborepo
- **Test**: Vitest + Playwright

## Key Directories

- `apps/web/` -- TanStack Start frontend
- `apps/worker/` -- Hono API on CF Workers
- `apps/liff/` -- LINE Front-end Framework mini-app (Vite)

- `packages/domain/` -- DDD aggregates, value objects, domain services, events
- `packages/contracts/` -- Zod schemas, enums, shared types (inferred from Zod)
- `packages/line-api/` -- Typed LINE Messaging API client (direct fetch, no SDK)
- `packages/design-tokens/` -- Panda CSS preset with type-safe tokens
- `packages/sdk/` -- Public TypeScript SDK for external integrators
- `packages/mcp-server/` -- MCP server for AI agent integration

## Conventions

- All IDs are UUIDv4, generated by `crypto.randomUUID()`
- Dates stored as ISO 8601 TEXT in SQLite
- Enums defined once in `packages/contracts/src/enums.ts`, used everywhere
- Zod schemas are the SSOT: types inferred via `z.infer<>`, not manually defined
- Repository functions take drizzle DB instance as first parameter
- Domain aggregates are pure (no I/O); services orchestrate repositories + aggregates
- Frontend routes: TanStack Query hook -> domain component -> route component (< 80 lines)
- No useState for server data (use TanStack Query)
- No localStorage for secrets (httpOnly cookies only)
- Japanese UI text, English code/comments
- Cap'n Web RPC for all authenticated API calls; REST only for external webhooks/public endpoints

## Hono Middleware Stack

Worker (`apps/worker/src/index.ts`) uses this middleware order:
1. `requestId()` -- unique request tracing ID
2. `logger()` -- structured request/response logging
3. `timing()` -- Server-Timing performance headers
4. `secureHeaders()` -- security headers (X-Content-Type-Options, etc.)
5. `cors()` -- CORS (restrict origin in production)
6. `prettyJSON()` -- ?pretty query param for debugging
7. `dbMiddleware` -- Drizzle DB injection (`c.get('db')` returns typed `Database`)
8. `errorHandler` -- global error handler (HTTPException, ZodError, unhandled)
9. `authMiddleware` -- Bearer token + staff validation (skips public routes)

Custom middleware in `apps/worker/src/middleware/`:
- `db.ts` -- Drizzle DB injection via `createMiddleware` + ContextVariableMap augmentation
- `error-handler.ts` -- structured JSON error responses with Zod validation details
- `validate.ts` -- `validateBody(schema)` / `validateQuery(schema)` for type-safe request validation
- `auth.ts` -- authentication (existing)
- `role-guard.ts` -- RBAC (existing)

## Database

- 42+ tables in Cloudflare D1 (SQLite)
- Schema in `packages/db/src/schema/` (Drizzle definitions)
- Migrations in `packages/db/migrations/` (Drizzle Kit generated)
- Soft deletes via `deleted_at` column (repositories filter by default)
- Audit trail via `created_by`, `updated_by` columns
- Run migrations: `pnpm db:generate && pnpm db:migrate`

## Forbidden

- Do NOT use `@line-official-account/messaging-api` SDK
- Do NOT use `localStorage` for API keys or secrets
- Do NOT use raw SQL (always use Drizzle ORM via repositories)
- Do NOT define types manually if a Zod schema exists (use `z.infer<>`)
- Do NOT use Next.js patterns (`getServerSideProps`, `'use client'`, etc.)
- Do NOT put business logic in route handlers (use domain services)
- Do NOT use magic strings for enums (import from `@line-crm/contracts`)
